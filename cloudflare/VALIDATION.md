# Проверка Cloudflare Bridge — 2026-10-28

Проверено локально без личных ключей, сессий и реальных сообщений:

- `npm ci`: воспроизводимая установка из lockfile.
- `npm run check`: TypeScript без ошибок.
- `npm test`: 15/15 тестов на настоящем локальном workerd/D1 через Miniflare;
  Telegram API заменён проверяемым mock, все исходящие запросы перехватываются.
- Проверены секретный заголовок, чужой/сменившийся владелец, подменённый connection ID,
  отключённое подключение, пустой allowlist, типы чатов, неподдерживаемые события,
  ограничение размера, ошибки Telegram/D1, отсутствие публичного чтения и утечек
  синтетических секретов/текста в захваченные логи.
- Конкурентные повторы, повтор с другим update ID, полное закрытие/открытие Miniflare
  с той же базой: метаданные сохраняются, повторная запись не появляется.
- Те же 15 тестов прошли на Node 22 в Docker с `--network none` и readonly
  mount исходников; основной локальный запуск — Node 24.19.0.
- Wrangler dry-run собирает Worker; ничего не развёрнуто.
- `npm run migrate:local` дважды: применение 0001, затем отсутствие новых миграций.
- `python3 -m unittest discover -s test -p 'test_*.py'`: 3/3, регистрация только с
  подтверждением, нужные allowed_updates, запрет редиректов; HTTP замокан.
- Регрессия Python MVP: `tools/test_postgres.py`, 142/142 теста SQLite/PostgreSQL,
  восстановление очереди после рестарта PostgreSQL. Ruff check/format проходят.
- Сборка существующего `Dockerfile.codex` с CA среды и offline smoke
  `tools/test_container.py`: права, отсутствие секретов, миграция, блокировка
  второго экземпляра и SIGTERM — успешно. Production Dockerfile не изменён;
  сборка с ним в GitHub Actions отдельно не подтверждена этим локальным запуском.

Новый каталог исключён из Docker build context для Python: `.dev.vars`, npm и
локальное D1-состояние не попадают в контекст существующего контейнера.
`railway.toml`, `config/default.toml`, Python runtime и их секреты не менялись.

Не проверено: настоящий Telegram Business webhook/права аккаунта, удалённый D1,
Cloudflare deploy/лимиты и живой перезапуск на Cloudflare. Регистрация webhook и
live-интеграции не выполнялись. Новые GitHub Actions не считаются успешными до
проверки конкретного run/SHA; во время подготовки GitHub API был заблокирован
сетевой политикой среды (CONNECT 403). Это ограничение создания PR/проверки CI,
не результат тестов приложения.

Для выпуска владелец сначала проверяет PR, затем отдельно разрешает deploy,
создаёт выделенного бота и D1, вводит секреты непосредственно в Cloudflare,
запускает личную Termux-регистрацию и выполняет controlled metadata smoke из README.
