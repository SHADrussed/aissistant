# Отдельный Telegram-бот уведомлений

Это отдельная сущность: bot token не заменяет личный Telethon StringSession.
Бот нужен и при Gmail-only режиме; личная авторизация Telegram в этом случае
не требуется. До live-подтверждения бот в worker не используется; отдельную
тестовую отправку владелец запускает вручную по инструкции ниже.

1. На личном устройстве откройте официальный https://t.me/BotFather, проверьте
   username **@BotFather**. Отправьте `/newbot`, задайте имя и уникальный username
   с окончанием `bot`. Не используйте бота, обслуживающего другой проект.
2. Полученный token оставьте только на своём устройстве/в менеджере секретов.
   Не вставляйте его в URL браузера, командную строку, Git, Codex или «ID helper bots».
3. В BotFather можно отключить добавление в группы через `/setjoingroups` → Disable.
   Администраторские права, каналы, inline mode, webhook и команды приложению не нужны.
   Не подключайте бота к внешним конструкторам — они получат доступ к его token.
4. Откройте **личный диалог** с новым ботом от аккаунта владельца и нажмите Start
   (отправьте `/start`). Сам бот на него не отвечает: обработчика команд в MVP нет.
5. На доверенном личном устройстве, подготовленном по
   [инструкции авторизации](personal-authorization.md), выполните:

   ```bash
   uv run --frozen --extra local-auth python tools/local_authorize.py bot --personal-device
   ```

6. Введите token только в скрытый локальный prompt. Утилита использует `getMe`,
   `getWebhookInfo` и `getUpdates`; **ничего не отправляет**. Существующий webhook
   приводит к отказу — не удаляется автоматически. Нужен новый dedicated bot.
7. Утилита принимает ровно одного private отправителя `/start` и показывает token
   и его положительный `TELEGRAM_OWNER_CHAT_ID` только в локальном маскированном окне.
   Если отправителей несколько или updates отсутствуют, не угадывайте ID: проверьте,
   что это новый бот и правильный аккаунт, затем повторите `/start` с личного устройства.
8. Если включаете и Telethon, сравните owner ID с `TELEGRAM_OWNER_CHAT_ID`, полученным
   на вашем устройстве при личной авторизации. Он должен соответствовать владельцу.
   Сохраните token и ID в Railway Variables, по возможности Seal, закройте окно,
   очистите clipboard. Не добавляйте ID группы вместо private owner.

## Отправить одно тестовое уведомление из Railway

После deploy версии с этой командой оставьте `mode="synthetic"`, источники
выключенными, а `ALLOW_LIVE_READS` и `ALLOW_AI_PROCESSING` выключенными/отсутствующими.
Нужны только уже добавленные runtime Variables `TELEGRAM_BOT_TOKEN` и
`TELEGRAM_OWNER_CHAT_ID`. Секреты в команду не вставляйте.

В Railway откройте shell/SSH **работающего контейнера** нужного service, если
доступно в вашем интерфейсе, и выполните один раз:

```bash
/app/.venv/bin/aissistant --test-notification
```

Если shell доступен только через CLI, на личном компьютере используйте
официальный Railway CLI: `railway login`, `railway link` (нужный проект), затем
`railway ssh` и ту же команду внутри контейнера. Проверьте выбранные service и
environment. Не используйте `railway run`: это запуск локально с runtime secrets.
Не задавайте тестовую команду как Start Command или cron: каждый её запуск
отправляет новое уведомление и завершает процесс, что может вызвать повторы.

В вашем личном диалоге с ботом должно появиться фиксированное сообщение:
«Тест ИИ-секретаря: доставка уведомлений владельцу работает.
Переписка не читалась, OpenAI не вызывался.» Успех: код выхода 0 и
`test_notification_sent`. Ошибка: код 1 и
`test_notification_failed_check_bot_configuration`, без токенов и traceback.
При ошибке проверьте Variables, личный owner ID, `/start`, блокировку бота и
доступность Telegram. Не пересылайте значения переменных в чат.

Команда не загружает worker-конфигурацию, не открывает БД/очередь, не создаёт
Telethon/Gmail/OpenAI clients, не читает переписку. Сначала проверяет `getChat`
на private owner, затем делает один `sendMessage`. Автоматических повторов нет;
при потере подтверждения сообщение могло уже прийти — проверьте диалог перед
повтором. Успех проверяет только маршрут бот → владелец, не реальные источники.

## Гарантии приложения и ограничения

- Runtime вызывает только `getChat` и `sendMessage` с одним ID из env; `getChat`
  должен подтвердить `private`. `_call` отвергает другие методы/получателей до HTTP.
- Нет polling/webhook/обработчика команд бота в worker. Текст источника и вывод
  модели не могут назначить получателя, добавить инструменты или отправить ответ
  собеседнику. Черновик — только поле карточки владельцу, без кнопки auto-send.
- Сообщения без parse_mode и preview; темп около одной карточки в секунду, 429
  выдерживает retry_after. При неопределённом подтверждении возможна повторная
  карточка — Bot API не предоставляет нужного idempotency key для exactly-once.
- После **отдельного live-подтверждения** проверяйте доставку только контролируемым
  новым сообщением в разрешённом чате/почте. Не отправляйте массовую личную историю.
- При утечке в BotFather отзовите/перевыпустите token, замените runtime secret,
  перезапустите один worker и проверьте private recipient. Не публикуйте старый token
  даже после отзыва.
