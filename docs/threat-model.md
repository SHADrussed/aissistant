# Модель угроз

Область: single-tenant MVP из docs/architecture.md; это модель проекта, не отчёт
о проверке реальных интеграций. Недоверенный отправитель контролирует текст
в разрешённом чате/почте. Оператор и облачный runtime доверенные; компрометация
их учётных записей выходит за защитные возможности приложения.

| Актив / граница | Угроза | Мера и проверка | Остаточный риск |
|---|---|---|---|
| Telegram → worker | Чтение чужих или ещё не разрешённых чатов | Двойной opt-in, receive_updates=False и explicit allowlist / отдельный двойной opt-in all до создания адаптера; тесты запрета | StringSession сама по себе даёт полный доступ к аккаунту |
| Runtime secrets → SDK | Утечка сессий/токенов | Только env, StringSession в памяти, git/docker ignore; никаких login утилит в worker | Администратор runtime может прочитать env; ротация вне приложения |
| Письмо/сообщение → модель | Prompt injection, ложные приказы, эксфильтрация | Текст — только данные; строгая Pydantic-схема, модель без tools; ссылка и получатель вне вывода модели | Галлюцинации/ошибочная классификация; черновик требует проверки человеком |
| Worker → OpenAI | Ненамеренная передача персональных данных | Отдельное согласие, ограничение длины, без вложений; store=false | Провайдер видит переданный текст; нужна оценка договорных условий |
| Worker → Bot API | Отправка третьему лицу, опасные ссылки/форматирование | Статический положительный owner ID, getChat(type=private), plain text, без preview; исходные ссылки только из адаптеров | Взлом бота/аккаунта владельца; синтезированная моделью ссылка может быть текстом, не следует ей доверять |
| OAuth → Gmail | Избыточные права | Токен с единственным gmail.readonly; проверка scopes tokeninfo при инициализации | Refresh token нужно отзывать вручную; readonly всё равно разрешает всю почту |
| SDK/HTTP → логи | Текст сообщений, токены в URL/exception | Только фиксированные event-коды; отключены сторонние логи; тесты redaction | Дамп памяти/платформенная диагностика вне контроля приложения |
| Worker → БД/backup | Доступ к сводкам и черновикам | Не сохранять raw text, retention доставленных сводок, volume права, no public DB | Сводки также персональные данные; шифрование диска/backup обеспечивает оператор |
| Внешний сервис → цикл | Rate limit, timeout, падение, дубли | Таймауты, backoff, durable outbox, уникальные seen, курсор после обработки; тесты сбоев | Telegram FloodWait выдерживается между циклами; длительный outage создаёт backlog |
| Входные данные → ресурсы | Огромный текст, бесконечная работа | Ограничение текста/вывода, batch Telegram, лимит уведомлений за цикл | Gmail окно может содержать много писем; нужны квоты и мониторинг |
| Deploy → состояние | Потеря БД/дубли при масштабировании | Persistent volume, одна реплика, отдельные БД synthetic/live, отказ SQLite live без persistent пути в инструкциях | DB session lock/flock предотвращают обычный overlap; нет exactly-once/fencing при сетевой неопределённости |

## Требуемые проверки

Unit/contract-тесты с fake transport: opt-in, allowlist, отсутствие авторизации,
scopes OAuth, курсоры/перезапуск, сбой классификации, сбой отправки, валидация
ответа модели, отсутствие чувствительных логов. Синтетический CLI smoke test
без сети. PostgreSQL 17 проверен на отдельном одноразовом сервере. Реальные внешние API
требуют отдельной авторизованной проверки после подтверждения владельца.

## Реагирование

При утечке: остановить worker, отозвать Telegram-сессию в Devices, OAuth grant,
BotFather token и OpenAI key; удалить чувствительные артефакты/backup по политике.
Не выводить секреты при расследовании. Перед повторным запуском пересмотреть
allowlist, owner ID и настройки доступа Railway.

## Реализованные границы и доказательства

- `config.py:Settings.validate_live`: два явных разрешения, конфигурация источников,
  проверка allowlist и наличия доступа только к выбранным peers.
- `sources.py:TelegramSource`: InputPeer из explicit allowlist либо подтверждённого
  all discovery, baseline и курсор каждого чата, без личной авторизации; FloodWait в состоянии БД.
- `sources.py:GmailSource`: tokeninfo, History API, проверка привязки аккаунта,
  курсор после всей пагинации; 404 history требует ручного решения.
- `classifier.py:OpenAIClassifier`: структурированный вывод, store=false, без tools.
- `notifier.py:BotNotifier`: один private owner, plain text, без preview, pacing.
- `store.py`/`worker.py`: атомарные seen/outbox, повторы после сбоя доставки, retention.
- `main.py:setup_logging`: только собственные фиксированные события в логе.

Это меры проекта и проверки синтетическими/поддельными данными, не подтверждение
безопасности облачного аккаунта или авторизованных внешних интеграций.

## Дополнительные угрозы v0.2

| Граница | Мера | Остаточный риск |
|---|---|---|
| all discovery → доступ ко многим чатам | confirm_all + ALLOW_TELEGRAM_ALL, исключения типов/IDs, baseline без backfill | Metadata содержит peer hashes и иногда последнее сообщение; кэш БД чувствителен |
| Личная переписка → OpenAI | local_only по умолчанию, исключения sender/chat/keywords, secret heuristics до HTTP | Не все секреты обнаружимы; группу нельзя автоматически считать непубличной |
| Входящие → стоимость | Резерв до HTTP, requests/day/cycle, no SDK retries, durable usage | Тарифы задаёт оператор; резерв консервативен, внешние расходы не учтены |
| Входящие → поток сообщений боту | Приоритеты, bounded digest, durable hourly cap | Ошибка модели может повысить приоритет; Critical тоже задерживается лимитом |
| Low → хранение личной информации | По умолчанию metadata-only, retention даже незапрошенного Low | Summary, ID и ссылки в БД всё равно требуют защиты |

Ключевые проверки: test_monitoring.py, новые cases test_integrations.py,
versioned v1 migration и SQLite/PostgreSQL copy в test_database.py.
